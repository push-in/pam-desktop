# Internationalization

The framework has no fixed interface text in one language. Every default it shows (placeholders, accessibility labels, menu roles, validation messages, chart and dialog titles, the host chrome) comes from a small catalog, with English as the base and Portuguese (`pt`) and Spanish (`es`) included. Your own copy can use the same `Pam\Desktop\I18n\I18n` catalogs and `I18n::t()` (`namespace.key` keys, `{name}` placeholders, plural forms).

## Choosing the language

| Level | How | Wins over |
| --- | --- | --- |
| System | `LC_ALL`, `LC_MESSAGES`, then `LANG` (empty, `C` and `POSIX` are skipped); else the locale the host reported (`useLocale()`); else English. | |
| App | `I18n::use('pt-BR')` once at boot. A later change reaches what renders next; components already created keep the defaults they were built with. `I18n::use(null)` follows the system again. | System |
| App, one text | The same key under the `pam` namespace of an app catalog. | The framework catalog |
| Component or call | The argument: `placeholder:`, `label:`, `emptyMessage:`, `locale:`, `Menu::edit('Edição')`, `new Required('…')`, `Files::save(…, title: '…')`. | Everything |

```php
use Pam\Desktop\I18n\I18n;

I18n::use('es');                                                     // the app language
I18n::catalog('fr', ['pam' => ['select.placeholder' => 'Choisir']]); // a language or one text
```

A language without a framework catalog gets English, unless an app catalog for it provides the `pam` keys. A `pam` key registered only in the app's source catalog applies to every language.

## What is localized

| Where | Texts |
| --- | --- |
| DesktopUI | `Select`, `Autocomplete`, `MultiSelect` (placeholders, labels, empty and error messages, pagination, accessibility labels), `DatePicker` (placeholder and `DatePickerLocale::system()`), `Toast` close button, `Checkbox` and `MediaTile` accessibility labels. |
| Desktop | `MenuRole` labels, `Menu::edit()` and `Menu::window()`, the form rules (`Required`, `Email`, `Matches`, `MinLength`, `MaxLength`), `AsyncValue::offline()` and `stale()`, the navigation header search placeholder, the `Files::save()` dialog title, `Format` (its default locale is the framework locale). |
| Charts | The "No data" label of empty charts. |
| Host chrome | The share menu, the alert "OK" button, the header search fallback and the release error screen. They use `pam_desktop_ui::i18n` in Rust, which follows `I18n::use()` (sent to the host as `i18n.locale`) or the process locale. Text that PHP sends always wins. |

Native dialogs (save, open) get their title from PHP: the one the app passes, else the localized default. With an empty title the platform's own title is used. No backend keeps fixed strings; a backend that needs one adds a `Text` to `pam_desktop_ui::i18n`.

Developer messages (exceptions, the development error overlay, warnings) stay in English.

## Keys

The keys and the three catalogs are in `Pam\Desktop\I18n\FrameworkText`, grouped by prefix: `select.`, `multiSelect.`, `autocomplete.`, `list.`, `toast.`, `media.`, `checkbox.`, `datePicker.`, `calendar.` (months and weekdays are `|`-separated lists), `files.`, `chart.`, `navigation.`, `form.` (`{length}` is filled), `async.` and `menu.` (the `MenuRole` values). `FrameworkText::get($key, $params, $locale)` reads one, `FrameworkText::locale()` tells the tag in use.

## Tests

`packages/desktop-ui/tests/i18n.php` covers the system locale, `I18n::use()`, app catalog overrides, explicit arguments and the save dialog title in the three languages. Tests that check a default text compare it with `FrameworkText::get()` or set the language first, so they pass on any machine locale.
